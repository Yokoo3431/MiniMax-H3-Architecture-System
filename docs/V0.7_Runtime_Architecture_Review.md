# MiniMax H3 V0.7 Runtime Architecture Review Report

> **Document Version**: `v0.7.0-design`
> **Target Baseline**: `v0.6.5 Production Deployment Ready`
> **Scope**: Runtime Modularity & Extensibility Audit for Architecture AI Engine

---

## 1. Executive Summary

This document evaluates the existing `runtime/` engine (`h3_orchestrator.py`, `task_planner.py`, `workflow_selector.py`, `prompt_composer.py`, `hardware_adapter.py`, `comfy_executor.py`) to determine pluggability for V0.7 Architecture Intelligence features.

---

## 2. Technical Evaluation Questionnaire

### Q1: Does current architecture support Prompt Skill Engine insertion?
**Answer**: **YES**. `runtime/prompt_composer.py` is decoupled from `h3_orchestrator.py`. In V0.7, a new `runtime/prompt_skill_engine.py` can be plugged in directly between `TaskPlanner` and `HardwareAdapter` without breaking existing interfaces.

### Q2: Does current `workflow_selector` support complex architectural task classification?
**Answer**: **YES, WITH EXTENSION**. The V0.4/V0.5 registry schema in `configs/workflow_registry.json` already organizes workflows into `architecture_visualization` and `architecture_analysis`. In V0.7, the selector will parse intent schemas (lighting, motion, camera, building type) for granular matching.

### Q3: Does current Agent Router support multi-stage tasks?
**Answer**: **NEEDS EXTENSION**. Currently, `H3Orchestrator` executes a 1-stage linear pipeline: `Input Rendering -> Generation -> Output MP4`. To support quality evaluation loops (Critic Agent), V0.7 will introduce multi-stage loop iteration.

### Q4: Which modules require extension in V0.7?
1. `runtime/prompt_composer.py` $\rightarrow$ Upgrade to **Prompt Skill Engine** (`skills/architecture_prompt/`).
2. `runtime/hardware_adapter.py` $\rightarrow$ Upgrade to **Acceleration Skill Engine** (`runtime/acceleration/`).
3. `runtime/h3_orchestrator.py` $\rightarrow$ Add **Architectural Critic Agent Evaluation Loop**.

### Q5: Which modules MUST remain stable?
1. `runtime/comfy_executor.py`: ComfyUI REST API socket/polling protocol.
2. `hardware/detect_gpu.py`: Low-level GPU VRAM detection logic.
3. `launcher/` & `userdata/`: Isolated user assets and double-click launchers.
